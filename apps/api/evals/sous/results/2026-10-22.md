### Failures and fixes

- **Ten failing cases were application errors:** `data_freshness`, `below_par_to_order`,
  `below_par_count`, `below_par_shortest`, and `par_missing`, in both repeats. Windows rejects
  the Unix-specific `%-d` and `%-I` date-format flags. This broke deterministic tool execution
  and caused ten unresolved ground-truth fields. Shared portable formatting now preserves
  the same unpadded dates and 12-hour clock. The same defect in daily briefing and Team
  time-off/availability notifications was fixed. Regressions cover midnight, noon, minute
  padding, local date boundaries, and daylight-saving transitions.
- **Two failures were poisoned-history answer selection:** the model fetched facts but
  ended with `evidence_only`. Focused tracing reproduced `Answer:`-prefixed JSON and excessive
  selections; a first prompt revision also exposed selecting example IDs without calling
  a tool. Prompt 11 explicitly separates historical context from facts for the new turn,
  requires raw JSON and requested metrics, and the repair distinguishes missing facts from
  invalid selections. The strict renderer still rejects prose, unknown IDs and old IDs.
  Regression tests cover malformed/unknown selections and a poisoned historical ID, with
  and without a subsequent fresh tool call. No validation rule was relaxed.
- Eval JSON now includes raw model replies and executed tool arguments/timings, so intent,
  dates, repairs and selection failures can be investigated. The recording wrapper delegates
  inference unchanged; it is used only by the evaluation runner, never production logging.
- Desktop setup also required a configurable Compose PostgreSQL host port and removal of a
  tracked `node_modules` symlink pointing to another machine's macOS checkout. The existing
  dependency lockfiles are unchanged.

The initial Windows backend run had nine failures from the same date-formatting defect and

Intermediate focused runs also caught assertions tied to the previous retry wording and a

full suite. All 630 tests ran on the final source.

This verifies the complete fixed case set on one model digest and synthetic fixture, not
production readiness or broad statistical accuracy. Expected facts come from the same
deterministic tools as the application, so the gate is not an independent audit of their
arithmetic. Temperature zero still showed differences between focused and full runs; the
reports preserve intermediate failures. The confirmation case can include an unrequested
previous-period comparison, although every displayed fact is validated. Relevance/minimality
beyond case expectations remains a limitation.

The first desktop cold-start case took 69.33 seconds, within the unchanged deadlines. The
final run used an already loaded model; its latency is not a cold-start or production-load
benchmark. Live evaluation calls the orchestrator; HTTP history isolation, retention,
streaming, cancellation, retries and fallback are covered by the database/API regressions.
Real Square sandbox operation and deployed disconnect/load behavior remain separate checks.
`npm ci` reported five high-severity advisories in the existing locked dependency graph;
dependency upgrades were outside this evaluation and the lockfile was preserved.

### Reproduce on this desktop

With the stack running and the isolated database initialized, from `apps/api` in PowerShell:

```powershell
$env:DATABASE_URL = 'postgresql+asyncpg://chefos_app:chefos_app@localhost:55432/chefos_desktop_eval'
$env:MIGRATIONS_DATABASE_URL = 'postgresql+asyncpg://chefos_owner:chefos_owner@localhost:55432/chefos_desktop_eval'
$env:OLLAMA_URL = 'http://localhost:11434'
$env:SOUS_PROVIDER = 'ollama'
# These match the separately running Ollama server; setting them here only records metadata.
$env:OLLAMA_NUM_PARALLEL = '1'
$env:OLLAMA_FLASH_ATTENTION = '1'
$env:OLLAMA_KV_CACHE_TYPE = 'f16'
python -m uv sync --frozen
python -m uv run --frozen alembic upgrade head
python -m uv run --frozen python -m evals.sous.seed
python -m uv run --frozen python -m evals.sous.run --repeat 2 --gate --fixture square-simulator-400d-v1 --json evals/sous/results/desktop-full.json
```

Use a fresh dedicated database for an independent fixture; seed and eval use the current
business date. Set `TEST_DB_HOST=localhost:55432` when running the backend tests. The local
`.env` has `POSTGRES_PORT=55432` and matching host database URLs; Compose service connections
still use the internal PostgreSQL port. Ollama was installed under
`%LOCALAPPDATA%\ChefOS\runtime\ollama-v0.40.8`; its server must be launched with the cache
settings above. Its official release archive's SHA-256 was verified before extraction.
