## Environment and method

- Apple M2 Pro, 16 GB RAM; Ollama 0.40.8, local `qwen3:8b`, prompt `sous-prompt-8`.
- Model digest and quantization details, case/runner hashes and fixed run clocks are in each
  JSON report. After pausing, the runner gained a regression for freshness metadata (which
  has no numeric evidence cards), its case gained an explicit stream-status expectation,
  and case-file comments were updated. The 16 completed cases and their expectations did not
  change. Re-run the complete current source on the desktop.
- Application settings were unchanged: temperature 0, thinking disabled, 32,768 context
  tokens, 2,048 output tokens, and the existing timeouts/resource limits.
- Default f16 cache caused heavy memory pressure. The second full attempt used
  `OLLAMA_NUM_PARALLEL=1 OLLAMA_FLASH_ATTENTION=1 OLLAMA_KV_CACHE_TYPE=q8_0`, recorded in its
  metadata. Ollama documents these cache settings in its [FAQ](https://docs.ollama.com/faq).
- The dataset was synthetic: `square-simulator-400d-v1`, seeded at
  `2026-10-22T14:17:53.935105+00:00` into the isolated `chefos_live_eval` database. It uses the
  existing Square simulator, canonical ingestion, published schedule and inventory demos.
  No customer data or real integration credentials were used. PostgreSQL was 17.6.
- Expected values came from deterministic typed tools. Scoring checks complete facts,
  including metric, entity, period, sign and unit. A coincidentally matching number cannot
  pass. This checks selection against the tools, not an independent audit of tool arithmetic.
- Initial latency includes cold starts and competing local work; it is not a production
  performance benchmark. Two temperature-zero repeats are a consistency check, not a broad
  statistical claim about model accuracy.

## Run on the desktop

With the repo dependencies, migrated database, seeded demo and Ollama model available:

```sh
ollama pull qwen3:8b
make sous-eval ARGS="--repeat 2 --gate --json /tmp/sous-desktop.json"
```

For the same isolated synthetic fixture, use a fresh dedicated database ending in `_eval`,
set `DATABASE_URL` and `MIGRATIONS_DATABASE_URL` to it, apply migrations, then from `apps/api`:

```sh
uv run python -m evals.sous.seed
OLLAMA_URL=http://localhost:11434 uv run python -m evals.sous.run \
  --repeat 2 --gate --fixture square-simulator-400d-v1 --json /tmp/sous-desktop.json
```

The seed command uses the current business date, so ground-truth values are recomputed for
the desktop run. Keep the same model digest to compare model behavior. A default f16 run on
the larger machine should be recorded separately from these q8 results. Complete all 106
